# ADR-0031: 강제 장치를 걷어내고 지침과 리뷰로 일한다

상태: 채택 (#104 2단계, 2026-10-31 사용자 결정). [ADR-0030](ADR-0030-enforce-at-impact-boundaries.md)의 훅 범위와 2단계
보류를 대체한다. 대체되는 결정: [ADR-0004](ADR-0004-enforcement-layers.md)의 훅·스크립트 강제, [ADR-0013](ADR-0013-local-session-metrics.md)
세션 지표, [ADR-0016](ADR-0016-codex-trigger-eval.md) Codex 트리거 eval, [ADR-0028](ADR-0028-worktree-binding.md)의 위임 worktree 결속,
[ADR-0029](ADR-0029-behavior-eval.md) 결과 eval.

## 맥락

1단계(PR #105)는 훅 차단을 공개 Issue 텍스트로 좁혔다. 그런데 좁힌 경계를 지키는 데에도 리뷰가 열 차례 넘게
되풀이됐다. curl·wget·HTTPie의 옵션, GraphQL 주석, 요청 결합처럼 우회 형식은 끝이 없었고, 이 가드레일은 처음부터 다른
언어로 쓰면 지나가는 장치였다. 잠금·감사·측정 장치도 같은 문제를 안고 있었다.

- 시험 잠금은 Bash 명령의 쓰기 대상을 찾으려고 셸 해석기 약 600줄을 필요로 했다. 해석기가 놓친 쓰기는 doctor가
  사후에 비교했다.
- doctor, 지표·eval 실행기, 설치 비교기는 devflow 자신을 검사하고 재는 데 쓰였다. 사용 저장소의 개발 방향을 지키는
  데는 쓰이지 않았다.
- 무인 게시 큐는 직접 게시를 막지 못하게 되면 더 이상 경계가 아니다.

공개 워크플로 도구 7개를 다시 확인했다. 시험 파일 잠금, 저장소 감사 실행기, 모델 eval 실행기를 플러그인 기능으로
싣는 도구는 없었다. superpowers와 pstack은 "시험 말고 코드를 고친다"를 지침으로 두고, 공식 pr-test-analyzer는 리뷰에서
시험 변경을 본다. 검증·eval 스크립트를 두는 저장소(agent-skills, plugins)도 그것을 유지보수용 CI로만 쓴다.

## 결정

- 훅은 SessionStart(재개 카드), Stop(자율 계속), SessionEnd(세션 해제)만 둔다. Issue 쓰기와 시험 파일 쓰기를 막지
  않는다. 셸 해석기, 분석 자식 프로세스, 차단 기록, 편집 후 감사를 지운다. 대체할 해석기는 만들지 않는다.
- `devflow-state`는 Issue 입출력의 안내된 경로로 남는다. 공개 텍스트 필터는 그대로 둔다. 강제가 없으므로 무인 게시
  큐와 서명 키를 지운다. 자율 모드에서는 Issue 텍스트 쓰기를 거부하고, 내용은 장부 notes에 남긴다.
- 시험 잠금을 폐지한다. "코드를 고치고 시험은 고치지 않는다"는 지침과, 리뷰의 시험 diff 확인으로 옮긴다.
- `devflow-doctor`, `devflow-metrics`, `devflow-codex-eval`, `devflow-behavior-eval`, `devflow-install-check`를 지운다.
  CI의 통합 관문은 테스트다. 문서 링크와 예산은 리뷰가 본다. 트리거 eval은 필요할 때 `claude plugin eval`로 선택해 쓴다.
- 에이전트는 explorer, implementer, reviewer 셋으로, 단계 references는 아홉으로 줄인다. 프로필에는 `integration`,
  `branch`, `verify`만 남긴다. 옛 키는 무시한다.

## 결과

- 정당한 작업의 차단과 우회·보강의 반복이 사라진다. 플러그인 코드와 테스트가 수천 줄 줄고, 도구 호출마다 뜨던 분석
  프로세스가 없어진다.
- 에이전트가 Tool을 거치지 않고 게시하면 필터가 적용되지 않는다. 무인 실행 중의 직접 게시도 막지 못한다.
- 시험을 약하게 고쳐 통과시키는 일은 실행 전에 막지 못한다. 리뷰가 시험 diff를 놓치면 그대로 통합될 수 있다.
- 문서 링크·예산·로컬 경로 검사가 CI에서 빠진다. 사용 저장소의 형식 검사(standards)도 없어진다.
- 0.4.0으로 업데이트한 저장소는 시험 잠금, Issue 쓰기 차단, doctor를 잃는다. 과거 장부의 잠금 기록은 읽히지 않을 뿐
  지워지지 않는다.

## 대안

- 1단계 범위 유지(텍스트 게시만 차단): 기각. 우회 형식을 쫓는 비용이 남고, 보안 경계도 아니다.
- 일반 게시 명령만 막는 작은 차단: 기각(사용자 결정). 막을 수 있는 실수보다 장치를 유지하는 비용이 크다고 판단했다.
- 편집 도구만 잠그는 시험 잠금: 기각. 셸로 고치는 경우를 놓치고, 해석기 없이도 위임 결속과 프로필 잠금이 남는다.
- 실제 사이클 1~2개를 비교한 뒤 결정: 기각. 비교할 측정(metrics)과 사후 검사(doctor)를 지우기로 했으므로, 비교하려면
  측정 장치를 다시 만들어야 한다. 대신 다음 사이클들의 리뷰에서 시험 약화가 보이는지 관찰하고, 보이면 다시 정한다.
