# ADR-0019: /clear 전에 현재 세션을 명시적으로 인계한다

상태: 채택 (사용자 결정, #47).

## 맥락

Codex 0.160.0의 TUI에서 `/clear`를 실행해도 이전 thread가 즉시 종료되지 않아 세션 경고가 남았다.
새 SessionStart 입력에는 이전 thread id가 없다. 같은 저장소의 최근 세션을 이전 thread라고 추측하면 다른 사용 중인
세션까지 지울 수 있다. 별도로 SessionEnd는 연결 worktree에서 외부 git 조회가 지연되면 정리할 주 작업 트리를 놓쳤다.

## 결정

인계는 현재 세션이 자기 id를 아는 동안 명시적으로 한다. 에이전트가 작업 기록과 위임 작업을 마친 뒤 마지막으로
`release`하고 사용자가 `/clear`한다. 순서는 [동시 세션 계약](../../specs/ledger.md#동시-세션)이 소유한다.
정상 종료 훅도 유지하며, 경로 판정은 가드가 이미 쓰는 안전한 로컬 Git 메타데이터 판독을 재사용한다.
강제 종료·충돌처럼 훅이 없는 경우는 기존 30분 만료를 유지한다.

## 검토한 대안과 한계

- 마지막으로 기록한 세션을 새 세션 시작 때 지우기: 동시에 쓰는 다른 세션을 지울 수 있어 제외했다.
- `git` 제한 시간 늘리기: 종료 훅의 전체 제한을 소모하고 `/clear`의 구독 해제 문제도 해결하지 못한다.
- 호스트가 알려 주지 않는 종료 상태를 추론하기: 별도 생존 확인 체계가 필요해 이번 범위에서 제외했다.
- 사용자가 인계 없이 직접 `/clear`하면 경고가 남을 수 있다. 호스트가 이전 thread 식별자를 제공하거나 실제 종료 이벤트를
  보장하면 명시 인계의 필요성을 다시 검토한다. 관찰 근거는 [host-facts](../../research/host-facts.md#codex)에 있다.
