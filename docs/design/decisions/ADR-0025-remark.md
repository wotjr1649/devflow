# ADR-0025: 다른 Issue에 남기는 일반 의견은 상태가 아닌 remark로 제공한다

상태: 채택 (#77, #70).

## 맥락

`devflow-state`는 `create`를 뺀 모든 Issue 쓰기를 브랜치의 Issue로만 보낸다(#1, #6, #12). 다른 Issue의 상태 오염을
막는 제한이지만, 상태를 바꾸는 쓰기와 의견 댓글을 구분하지 않았다. 그래서 main이나 다른 Issue 브랜치에서 기존
Issue에 분석 의견을 남기려면 전용 브랜치를 만들어야 했고(#77), 작업 중 `create`로 만든 추적 Issue에도 후속 기록을
남길 수 없었다(#70).

## 결정

같은 저장소의 기존 Issue에 일반 의견만 다는 `remark`를 둔다. `comment`는 체크포인트 전용으로 남기고, remark는
체크포인트 형식을 거부해 재개 카드와 `read`가 상태로 읽지 않게 한다. 무인 실행은 거부한다. 대기열에 넣으면 flush의
대상 제한과 서명 범위가 넓어지기 때문이다. 무인 여부는 호출자 작업 Issue의 장부로만 판단한다. 대상 Issue의 장부는
다른 사람의 작업 상태라서 읽지 않는다.

## 결과

- #70의 추적 Issue 기록과 #77의 일반 의견이 한 명령으로 해결된다. 상태·본문·체크·종료 제한은 그대로다.
- main처럼 작업 Issue가 없는 곳에서는 무인 실행을 기계적으로 막지 못한다. 대화형 턴에서만 쓴다는 지침에 의존한다.
- 응답 유실은 요청 단위로 다시 읽어 확인할 뿐, 중복 게시를 영구히 막지는 않는다.

## 검토한 대안

- `create`로 만든 번호를 장부에 기록하고 그 Issue에만 `comment` 허용: 생성 응답 유실과 세션 간 인계를 다뤄야 하고,
  main의 일반 의견 문제는 남는다.
- 상태 블록이 지목한 번호에만 허용: 쓰기 가능한 데이터가 허용 목록이 된다.
- `comment --general` 같은 옵션: 같은 명령의 형식·대상·flush 의미가 갈라진다.
