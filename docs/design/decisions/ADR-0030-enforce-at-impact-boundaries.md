# ADR-0030: 강제는 영향 경계에만, 나머지는 안내로

상태: 채택 (#104, 2026-10-31 사용자 결정). [ADR-0004](ADR-0004-enforcement-layers.md)의 훅 범위,
[ADR-0013](ADR-0013-local-session-metrics.md)의 매 사이클 측정, [ADR-0029](ADR-0029-behavior-eval.md) 결과 eval의 위치를 좁힌다.

## 맥락

[개요](../overview.md)의 원칙은 모델 판단을 대신하지 않고 사람은 게이트에만 둔다는 것이다. 그런데 구현은 강제와 측정
쪽으로 커졌다.

- 훅은 셸 문법 전체를 해석하고, 확정하지 못하면 거부했다. 막는 규칙마다 리뷰가 새 우회를 찾아 보강이 이어졌다(#48,
  #52, #53, #69, #90). PR 리뷰 스레드 resolve처럼 Issue 텍스트가 없는 쓰기도 막혔다(#99 오탐 기록).
- 저장소별 보호 경로(`protected`)는 그 저장소가 스스로 정할 일인데 devflow가 맡았다.
- 결과 eval(#99)이 수용 기준이 되자(#73 기준 4), 기준 하나를 위해 실행기·보정·재측정이 커졌다. 그런데 14회 반복으로는
  1/14 차이를 가를 수 없었다.
- 매 사이클 측정과 리뷰 지적마다의 재리뷰가 작은 사이클에도 단계를 더했다. PR #102에서는 필터 하나에 재리뷰가 십여
  차례 돌았다.

Anthropic·OpenAI 공식 지침과 공개 워크플로 도구 7개를 비교한 결과([sources](../../research/sources.md#강제와-측정의-범위))는
다음과 같다. 결정적 강제는 영향이 큰 경계에 둔다. 행동 eval은 스킬 행동을 바꿀 때 소수 사례로 선택해 비교한다. 측정 점수를
병합이나 출시 조건으로 두지 않는다.

## 결정

- 훅이 막는 것은 Issue에 텍스트(제목, 본문, 댓글)를 게시할 수 있는 쓰기뿐이다. `devflow-state`의 공개 필터를 거치게 하기
  위해서다. 텍스트 없는 상태 변경, Issue가 아닌 GitHub 쓰기, 해석할 수 없는 명령은 막지 않는다. 시험 잠금과, 시간
  초과·내부 오류 때의 거부는 2단계에서 정할 때까지 그대로 둔다.
- `protected` 기능을 없앤다. 프로필에 남은 키는 무시한다. 프로필을 읽지 못해도 막지 않고 doctor가 알린다.
- 결과 eval은 요청할 때만 쓰는 도구이고, 그 결과는 수용 기준이나 출시 조건이 되지 않는다. 트리거 eval은 호출 필드가 바뀔
  때의 회귀 확인으로 남는다.
- 사이클 측정은 사용자가 요청했거나 비교 표본으로 정한 사이클에서만 한다. ship 체크포인트의 측정 줄도 그때만 쓴다.
- 리뷰 지적을 고친 뒤 다시 리뷰하는 것은 동작이나 권한을 바꾼 수정뿐이다. 같은 지점의 지적이 되풀이되면 덧대기 전에
  설계를 다시 본다.
- 2단계: 대화형 단일 세션의 장부 축소와, 시험 잠금을 차단에서 리뷰 확인으로 바꾸는 일은 1단계 뒤 실제 사이클 1~2개를
  비교해 정한다.

## 결과

- 정당한 작업의 차단과 우회·보강의 반복이 줄고, 작은 사이클의 절차가 가벼워진다.
- 해석할 수 없게 쓴 명령으로는 필터 없이 Issue에 게시할 수 있다. 의도적인 회피는 막지 않는다는 뜻이다.
- 재지 않은 사이클은 비용 추세 비교에서 빠진다. 결과 eval 없이 고친 스킬 문구의 효과는 미확인으로 남는다.

## 대안

- 현행 유지: 기각. 오탐과 보강이 이어지고, 노력이 장치 자신에게 들어간다.
- 훅 전체 제거: 기각. 공개 Issue 텍스트는 되돌리기 어려운 게시이고 프롬프트 주입 경로다.
