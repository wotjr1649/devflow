# ADR-0012: 기억 도구는 검색 계층이고, 교훈은 성격에 맞는 곳에 둔다

상태: 채택 (사용자 결정)

## 맥락

- "두 번 틀린 실수는 AGENTS.md에 추가"만 있으면 AGENTS.md가 계속 커진다. 크기 예산이 기계적으로 막아 주지만,
  넘친 교훈을 어디에 둘지는 정해지지 않았다.
- 소유자는 여러 기억 도구를 쓴다.
  - claude-mem: 세션을 시작할 때 최근 관찰을 주입한다.
  - 직접 만든 기억 도구: 두 호스트의 훅 이벤트를 수집한다.
  - Claude 자동 메모리
- 이 도구들이 저마다 기록을 가지면, devflow의 상태와 다른 내용이 컨텍스트에 들어올 수 있다.

## 결정

- 교훈은 learn 단계에서 성격에 따라 배치한다. 기계로 막을 수 있는 것은 훅·테스트·doctor로, 영역별 교훈은 문서와
  문서 지도로, 저장소 전체의 반복 실수만 AGENTS.md로 보낸다. 표는 [lifecycle](../../specs/lifecycle.md#회고와-기억)이
  정한다.
- 기억 도구는 검색 계층이다. 진실 원천은 Issue, git, spec, 결정 기록, AGENTS.md다. 충돌하면 진실 원천이 이긴다.
  devflow는 기억 도구에 직접 쓰지 않는다([documents](../../specs/documents.md#기억-도구)).

## 결과

- AGENTS.md는 예산 안에서만 늘어나고, 기계로 막히게 된 Gotcha는 지워진다.
- 기억 도구가 세션을 시작할 때 주입하는 양을 파일럿에서 측정한다.
- 나중에 기억 도구가 체크포인트와 결정 기록을 색인하게 하면, 진실 원천을 둘로 만들지 않고 검색을 강화할 수 있다.

## 검토한 대안

learn 단계가 기억 도구에 교훈을 직접 기록: 특정 도구에 의존하게 되고 진실 원천이 둘이 된다.
