# ADR-0005: 메인 우선 실행과 단일 작성자

상태: 채택 (사용자 결정: 메인 우선, 병렬 쓰기 조건부 허용, Codex는 가벼운 동등성). 개정: M4를 실행 모드에서 뺐다
([ADR-0017](ADR-0017-drop-m4-defer-route.md), #41).

## 맥락

- Claude Code 문서: 기획·구현·테스트처럼 맥락을 공유하는 단계는 메인 대화가 맡는다.
- Codex 문서: 병렬 에이전트는 읽기 위주 작업부터 쓰고, 병렬 쓰기는 충돌을 조심한다.
- Cognition: 여러 에이전트가 동시에 쓰면 행동에 담긴 드러나지 않은 결정이 충돌한다.
- Anthropic: 멀티에이전트는 토큰을 여러 배 쓰고, 작업은 맥락 경계로 나눠야 한다.

## 결정

- 실행 모드 M0~M3을 둔다. 기본은 M1이다. 메인이 쓰고, 읽기·검증·리뷰는 서브에이전트가 맡는다.
- 위임으로 구현하는 M2는 [orchestration](../../specs/orchestration.md#실행-모드)의 조건을 만족할 때만 쓴다.
- 병렬 쓰기 M3는 Claude 전용이다. 파일이 겹치지 않고 인터페이스가 고정된 작업만, worktree로 분리하고 동시에 2~3개까지.
- Codex는 내장 explorer·worker만 쓰고 M3을 쓰지 않는다.

## 결과

- 메인 컨텍스트가 길어진다. 재개 카드와 `/clear`로 다룬다.
- M2·M3는 계획에 작업별 interfaces가 있어야 한다.

## 검토한 대안

- 항상 위임 (superpowers의 subagent-driven development): 메인은 깨끗하지만 토큰이 여러 배 들고, 모든 작업에 상세 계획이 필요하다.
- 항상 메인: 큰 작업에서 compact가 잦아지고 탐색 결과가 메인 컨텍스트를 오염시킨다.
