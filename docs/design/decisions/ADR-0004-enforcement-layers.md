# ADR-0004: 규칙은 계층으로 강제한다

상태: 채택. 개정: eval 조건(#11)

## 맥락

스킬은 조언이라서 모델이 따르지 않을 수 있다. Claude Code 문서와 AI-native SDLC 플레이북 모두 반드시 지켜야
하는 규칙은 결정적인 장치로 받치라고 한다. Codex 문서는 도구 훅을 "완전한 경계가 아닌 가드레일"로 설명한다.

## 결정

- 기계로 판정할 수 있는 규칙은 `devflow-doctor` 스크립트 하나로 검사한다. 같은 스크립트를 스킬(분석),
  훅(편집 직후 알림), CI(실패 처리)가 함께 쓴다.
- 판단이 필요한 품질은 감사와 eval로 다룬다. 강제하지 않는다.
- 훅:
  - 재개 카드 (SessionStart)
  - `devflow-state`를 거치지 않는 Issue 쓰기 차단 (PreToolUse)
  - 보호 경로 차단 (PreToolUse)
  - 지침 파일 편집 시 감사 (PostToolUse)
  - 자율 모드 전용 계속 (Stop)
  - 수정 작업 중 테스트 파일 편집 차단 (PreToolUse, 프로젝트가 원할 때만)
- 자율 계속 훅은 장부의 `mode`가 `autonomous`일 때만 켜고, 같은 작업에 최대 2회만 작동한다. 처음에는 M2·M3 위임
  중도 넣었으나, 대화형 세션의 위임까지 붙잡는 모순이 점검에서 드러나 뺐다(사용자 결정).
- 수정 작업 중 테스트 파일 편집 차단은 `.devflow.json`의 `tests`를 적은 프로젝트에서 명령으로 잠글 때만 동작한다.
  훅이 놓친 셸 편집은 doctor가 관문에서 잡는다(#20, [ADR-0015](ADR-0015-paper-features.md)).
- 훅은 가드레일이다. Claude Code의 PreToolUse는 exit 2나 거부 결정일 때만 막고, 다른 오류와 시간 초과에는 그대로
  진행한다. 그래서 막는 훅은 예외를 모두 잡아 거부로 끝내고, 정상·거부·오류 경우를 `node:test` 고정 입력으로 검사한다.
  Codex 훅에는 exec form(`args`)이 없고 Windows 셸도 정해져 있지 않으므로, 셸이 해석할 문법이 없는
  `node -e "require(process.env.CLAUDE_PLUGIN_ROOT+'/...').main()"`을 두 호스트에 같이 쓴다.
- 명령 텍스트를 읽는 훅은 경계가 아니다. 실행 중에 조립한 단어, 훅이 풀지 않는 인코딩, 다른 언어의 HTTP 호출은
  지나간다(Claude Code 권한 문서도 Bash 규칙을 같은 이유로 경계가 아니라고 한다). 이 명령 파서는 OS sandbox를
  대신하지 못한다. Windows sandbox의 지원 범위는 [host-facts](../../research/host-facts.md#codex)를 따른다.
  닿는 범위는 호스트 권한과 GitHub 자격 증명의 범위에 달려 있다
  ([ADR-0014](ADR-0014-gh-token-scope.md)).
- 공개되기 전 마지막 관문은 git pre-push 훅이다. doctor(문서 검사를 흡수했다)와 테스트를 돌린다. 설치는 소유자 지시로 한다.
  devflow 저장소는 추적되는 `.githooks/pre-push`로 설치했다. CI 없는 통합에서는 이 관문이 커밋별
  검사 기록을 대신한다. 지시문으로 쓰게 한 검사 줄은 커밋마다 빠지곤 했기 때문이다(사용자 결정). devflow 저장소는
  처음의 main push·정보용 CI 결정은 #51에서 개정했다. 모든 push에서 실행하며, 변경 경로별 필수 여부와
  Issue 브랜치 정리는 [repository](../../specs/repository.md#통합과-ci)가 소유한다. 로컬 관문과 CI는 서로 대체하지 않는다.
- 트리거 eval은 스킬 목록(frontmatter의 호출 필드, 스킬 구성, eval 사례)이 바뀔 때만 돌린다. eval 실행은 격리되어 대상
  플러그인만 로드되고 호스트는 스킬 목록만 보고 호출을 정하므로, 본문·references·훅·AGENTS.md의 변경은 결과를 바꾸지 않는다.
  eval이 문제를 잡은 것은 #1의 description 변경뿐이었고, 본문만 바뀐 #6과 #8은 결과가 같았다. 결과 eval은 장치가 없어
  사이클마다 생략을 물었으므로 조건에서 뺐다. 기준은 [eval](../../specs/eval.md#eval)에 있다. (사용자 결정, #11)

## 결과

- 훅은 빠르고 범위가 좁아야 한다. 무거운 검사는 커밋이나 CI로 미룬다.
- 훅은 보호 경로를 판정하려고 `.devflow.json`을 링크를 따라가지 않게 연다. Windows의 Node에는 `O_NOFOLLOW`가 없어
  lstat, open, fstat, lstat의 inode를 대조해 바뀐 경로를 거부한다. 열기 자체는 링크를 따라가므로, lstat 뒤에 경로를
  바꾸면 다른 대상이 잠깐 열리고, 그 열기가 오래 걸리면 훅이 시간 초과로 끝날 수 있다. 읽은 내용은 대조에서 버린다.
  Node 내장으로는 원자적으로 막을 수 없어 알려진 한계로 둔다(#9, 사용자 결정).
- eval 실행은 사용량을 쓴다. 스킬 목록이 바뀐 사이클에서만 돌리므로, 본문만 바뀐 사이클의 동작 회귀는 리뷰와 지표로만 잡힌다.
- 대화형 작업에서는 자율 계속 훅이 동작하지 않으므로, 사용자가 언제든 끼어들 수 있다.

## 검토한 대안

- 스킬만 쓰기: 위반이 드물어질 뿐 막히지 않는다.
- 모든 규칙을 훅으로: 느리고 깨지기 쉽다.
