# Discover

**Exit:** confirmed intent enters start; a research-only request ends with findings; a spike ends with its experiment report; deferred work has a reason and explicit reopening condition.

**Input:** an actual uncertainty about the problem, desired outcome, or a risky assumption. A clear implementation request with observable acceptance already confirms intent; do not repeat an interview.

## Do

Read settled decisions and relevant project evidence before asking. Distinguish observation, reported claim, inference and unknown. Establish who is affected, what changes for them, why it matters, constraints, dependencies, exclusions and observable success. Compare plausible approaches with cost/risk, including using existing capability or building nothing when relevant; recommend the smallest approach that still satisfies the user's scope.

Ask only about choices the user owns or ambiguity that materially changes the work. Do not reduce requirements to fit a preferred solution. Record an Issue draft with the project's parsed intent headings and acceptance criteria; before tracking is authorized this remains a draft, with no Issue, branch, ledger or product edits.

A spike names its question, isolated throwaway location, permitted inputs/effects, time or attempt bound, proof and exit before experimentation. Report what was learned, limitations, and the start/design decision it enables. Spike output is not production implementation or accepted delivery evidence by itself.

For a tracked intent change, retain prior criteria/results, obtain any genuinely new user decision, replace intent through the trusted helper and reopen affected evidence. Existing authorization still applies to unchanged effects. Explicit partial deferral keeps remaining scope traceable with required successors; whole-task deferral records a reopening condition.

**Return:** unresolved consequential choice stays discover; disproved technical assumption goes design; implementation defects within confirmed intent go build rather than another interview. Name destination, reason and affected evidence.
