# ADR-0003: Issue를 상태의 진실 원천으로

상태: 채택 (사용자 관행 + 합의한 문서 체계)

## 맥락

- 기존 프로젝트들은 compact 뒤에도 작업을 잊지 않으려고 Issue로 추적해 왔다.
- 그런데 상태를 Issue 본문에 날짜별 섹션으로 계속 덧붙이고, 댓글이 수십 개씩 쌓인다.
- Issue와 같은 내용을 담은 긴 프롬프트와 handoff 파일도 따로 만든다.
- compact 뒤 호스트는 최근 파일 몇 개만 다시 읽고, 5,000토큰이 넘는 파일은 경로만 남긴다.

## 결정

- Issue 본문은 intent와 **덮어쓰는** 현재 상태 블록을 담는다.
- 댓글은 **추가만 하는** 체크포인트를 담는다.
- 세션이 시작되거나 compact되면 SessionStart 훅이 재개 카드를 출력한다.
- 작업 단위가 끝나면 `/clear` 후 재개 카드로 다시 시작한다.
- 공개할 수 없는 근거만 로컬 비공개 파일에 둔다.
- 형식과 예산은 [documents](../../specs/documents.md)가 정한다.

## 결과

- 이어서 작업할 때 읽는 양이 일정하다: Issue 본문과 최신 체크포인트 하나.
- 공개 저장소의 Issue에는 공개 가능한 요약만 쓴다.
- Issue 쓰기는 원격 쓰기다. 프로젝트별로 AGENTS.md에 상시 허용 문장이 있어야 묻지 않고 갱신한다.

## 검토한 대안

- 커밋되는 intent.md → spec.md → plan.md 체인(AI-native SDLC 플레이북): 계약 변경에는 `docs/specs/`로 채택했다.
  계획은 기존 프로젝트들이 비공개로 두어 왔으므로 기본은 로컬에 두고 PR에 요약만 남긴다.
- 로컬 진행 파일만 쓰기: 다른 기기나 다른 호스트에서 보이지 않는다.
