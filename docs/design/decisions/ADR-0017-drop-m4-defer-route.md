# ADR-0017: M4를 실행 모드에서 빼고 route 확장을 보류한다

상태: 채택 (사용자 결정, #41). [ADR-0015](ADR-0015-paper-features.md)의 M4 결정을 대체한다(superseded).

## 맥락

- [ADR-0015](ADR-0015-paper-features.md)는 M4(Workflow로 하는 대규모 변경과 감사)를 "사용자가 직접 실행하는 모드"로
  남겼다. 그 뒤로도 M4는 devflow가 배포하지도, 고르지도, 기록하지도 않는 모드로 남았다. 경로 규칙은 어느 경로도 M4로
  보내지 않고, 스킬과 에이전트에도 M4 언급이 없다. 그런데도 실행 모드 표와 장부 `runMode`(M0~M4)에 이름이 남아
  설계와 리뷰가 그것을 전제로 삼았다.
- 서브에이전트의 모델과 effort를 정하는 route는 지금 [orchestration](../../specs/orchestration.md#모델과-effort)의
  표와 승격 규칙이다. 다른 역할의 effort 승격과 PreToolUse 훅(`updatedInput`) 강제는 "파일럿에서 부족함이 확인되면"
  검토하기로 열려 있었다.
- 측정(#2~#39, 사이클 38개): 승격 0회, 수정 루프 3회. 모델 호출은 메인 세션의 Opus가 대부분이고, 서브에이전트는
  약 10%다.
- 확인한 호스트 동작(2026-10-04):
  - Claude Code는 서브에이전트 effort를 정의에서만 정한다.
  - 호출할 때 모델을 바꾸는 훅 강제는 공식 문서에 없고, 커뮤니티 보고뿐이다.
  - Codex `spawn_agent`의 도구 설명은 사용자가 명시적으로 요청하지 않으면 모델을 정하지 말라고 한다.
  - Codex 플러그인은 에이전트를 배포할 수 없다.

## 결정

- **M4**: 실행 모드에서 뺀다. 실행 모드는 M0~M3이고, `devflow-state ledger-update`는 `runMode` M4를 거부한다.
  사용자는 Workflow를 devflow 밖에서 그대로 직접 실행할 수 있다. devflow가 하지 않는 일을 모드 이름으로 두지 않는다.
- **route 확장**: 보류한다. 표와 승격 규칙은 그대로 두고, spec과 어긋난 `implementer-deep` 설명만 바로잡는다.
  역할별 effort 정의를 더하는 일, 훅 강제, 선언형 route 명령, Codex 역할 에이전트 설치는 하지 않는다.
  사용자 판단으로는 이 플러그인과 맞지 않고, 측정으로도 승격이 필요했던 적이 없다.

## 다시 볼 조건

- M4: Workflow를 devflow 사이클 안에서 반복해서 쓰고, 그 결과를 장부나 측정에 남겨야 할 때.
- route: 승격이 실제 사이클에서 반복되거나, 같은 역할의 품질 부족이 리뷰와 지표로 두 번 이상 확인될 때.
  Codex에서 표의 모델이 적용되지 않아 결과가 달라지는 것이 확인될 때도 다시 본다.

## 검토한 대안

- **M4를 사용자 실행 모드로 유지(ADR-0015)**
  - 장점: 바꿀 것이 없다.
  - 기각 이유: devflow 안에서 동작이 없는 이름이 표에 남는다(사용자 결정).
- **route를 선언형 명령이나 훅으로 강제**
  - 장점: 결정적이고 시험할 수 있다.
  - 기각 이유: 승격이 쓰인 적이 없다. Claude의 훅 강제는 문서에 없는 동작에 기댄다. 고위험 훅 코드가 늘어난다.
- **Codex 역할 에이전트(`~/.codex/agents/*.toml`) 설치**
  - 장점: Codex에서 모델과 effort가 실제로 적용되는 유일한 경로다.
  - 기각 이유: 호스트 설정을 바꾸는 일이고, 지금은 필요가 측정되지 않았다.
- **학습형 router나 모델 프록시**
  - 기각 이유: 학습할 데이터가 없다. 프록시는 호스트의 네트워크와 인증을 바꾸고, 작업 난이도가 아니라 요청 종류로 나눈다.
