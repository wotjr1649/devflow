# ADR-0022: sub-issue 연결을 devflow-state의 제한된 관계 작업으로 제공한다

상태: 채택 (#59).

## 맥락

직접 Issue 쓰기를 막는 가드는 sub-issue 연결에도 적용되지만 공식 스크립트에 연결 기능이 없었다.
후속 Issue의 부모·자식 번호는 현재 작업 브랜치 번호와 다를 수 있어 기존 본문 쓰기 제한만으로도 지원할 수 없다.

## 결정

[Issue 입출력](../../specs/issues.md#issue-입출력)에 같은 저장소 관계 추가만의 예외를 둔다. 작업 문맥과 연결 대상을
분리하고 기존 본문·댓글 제한과 직접 API 가드를 유지한다. 명령과 서명은 사용자 권한을 대신하지 않는다.
연결·목록만 제공하고 부모 교체·해제·정렬·다른 저장소·일괄 처리는 추가하지 않는다.

부모 없음은 성공한 GraphQL metadata 응답의 nullable parent로 확인한다. REST 404는 접근 불가나 대상 없음과
혼동될 수 있다. 숫자·저장소·전체 응답을 검사하고 서버 응답 본문·제목을 출력하지 않는다.
내부 ID는 Int 범위보다 큰 값도 표현하는 fullDatabaseId로 읽고 안전하게 표현할 수 없는 값은 거부한다.
기존 MAC이 보호하는 text에 버전과 두 번호를 넣어 대기열 형식·서명의 호환성을 유지한다.

미확인 POST는 다음 flush에서도 조회만 한다. 기존 대기열의 claim·제거·수동 drop을 재사용하며 범용 승인·소비 기록
시스템은 만들지 않는다. HMAC은 큐 무결성이고, 같은 사용자의 조작과 옛 유효 항목 재생은 기존 큐의 한계다.

## 대안과 검증 한계

- 직접 API 예외: 검증·무인 대기열 경로를 분리하므로 기각.
- 부모 브랜치만 허용: 후속 Issue를 만든 작업에서 연결할 수 없으므로 기각.
- 생성과 연결을 결합: 부분 성공·실패 재실행을 늘리므로 현재 범위에서 제외.

조회와 POST는 원자적이지 않고 목록도 snapshot이 아니다. 외부 actor의 transfer·관계 변경을 완전히 잠그지 못하며
결과는 재조회 시점의 관찰이다. 계층 순환·한도 거부는 서버 계약으로 남기고 실제 API 시험에서 확인한다.
로컬 시험·CI와 실제 API·호스트 실행은 별도 증거이며, 설치·릴리스는 별도 실행 지시를 따른다.
