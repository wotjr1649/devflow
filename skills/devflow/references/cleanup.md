# Cleanup

**Exit:** each selected branch/worktree/ref is either removed with current proof or retained with a concrete reason; preserved inputs/history/evidence remain recoverable. Readiness assessment alone performs no deletion.

**Input:** authorized cleanup targets, observed integration, exact local/remote identities, current occupancy and preservation requirements. Issue closure and cleanup authority are separate.

## Checklist

1. Inventory selected tips, intended integration target, PR/result, linked worktrees, locks, users/processes, submodules, staged/unstaged/untracked/ignored contents and unique commits. Retain main/default/protected branches, active or unowned worktrees and unrelated work. Lease expiry is not proof another writer stopped.
2. Prove integration into the intended destination, not merely some upstream. Squash/rebase delivery needs content/history reconciliation and preservation of unique commits. Refresh current tips before effects; stale or incomplete proof holds only the affected removal.
3. Preserve required local inputs and the sole copies of check/review/handoff evidence before disposal. Uncommitted work needs an authorized preservation/discard decision; never infer it is disposable from age, filenames or generated-looking contents. Do not force removal even to work around a refusal.
4. If authorized archival is needed, use a unique ignored destination outside the target, normally the primary workspace's `artifacts/worktree-archive/`. Verify real paths; do not follow changed links/reparse points, overwrite existing artifacts or copy secrets without authority. Record original root, refs/SHAs, path inventory, size/hash/needed metadata and restoration instructions, including index/worktree differences. A Git bundle does not preserve local files. Verify the copy and required restoration properties before removing the source. Changed source, unsupported metadata or failed verification means retain it. Avoid archiving reproducible repository content merely to simplify deletion.
5. Use nonforcing `git worktree remove` and `git branch -d` on verified local targets. Refusal leaves a hold; no `--force`, `-D`, reset/clean, manual folder deletion or hook bypass as an alternate route. Prune only confirmed stale metadata, never another task's occupied worktree.
6. Read the trusted helper's `delete-destination <remote>` and verify that exact destination. Create `{remote, ref, expectedOid, expectedDestination}` in that field order. Prepare a protected `branch-delete` effect with that object as `payload`, target `git:<remote>:<ref>` and its exact digest (`help workflow` defines encoding), then execute the same object with `conditional-delete <issue> < deletion.json`. This compares the reviewed full ref/SHA atomically and refuses destination drift. Its narrow expected-SHA lease authorizes no other force push. A stale expectation preserves the ref; never replace it with an unreviewed tip or destination to obtain success. Hold configuration/remote ownership through execution: live Git configuration and transport are not isolated by this helper. `ls-remote` followed by ordinary deletion is insufficient. Missing capability, ownership or proof leaves this removal pending; independent safe cleanup continues.
7. Read back uncertain effects before retrying. Update the surviving ledger after branch removal through the supported helper; retain the evidence needed to reconstruct the result. Report removed, retained, archives verified and remaining action/revisit condition.

**Return:** unproven integration → ship; unexplained delivery loss → review/design reconciliation; dirty/unique/live/unknown target → cleanup hold with exact evidence or decision required. Record destination, reason and affected evidence. Do not offer forced deletion or claim cleanup succeeded when a target remains unresolved.
