# ADR-0021: M0의 적용 조건과 마무리를 명확히 한다

상태: 채택 (#58).

## 맥락

M0는 이미 메인의 검사와 diff 재검토로 검증·리뷰를 마치는 모드였다. 그러나 lifecycle 표는 새 컨텍스트 검토를
일괄적으로 적었고, 문서 변경에서도 원격 Issue 브랜치 push와 정보용 CI 대기를 추가할 수 있었다.
Markdown 지침이 실행 판단을 바꾸는 devflow에서는 확장자만으로 작은 변경을 판별할 수도 없다.

## 결정

- 새 모드 없이 [M0의 의미 기준과 마무리](../../specs/orchestration.md#m0의-적용과-마무리)를 명확히 한다.
  M0는 단계 생략이 아니며, 지침의 실행·권한·공개·신뢰·검사 규칙 변경을 단순 문구 정리와 구분한다.
- [통합과 CI](../../specs/repository.md#통합과-ci)의 필수·정보용 구분을 그대로 적용한다.
  필수 CI 대상이 아닌 local-merge 변경에만 원격 작업 브랜치 push·정보용 CI 대기를 추가하지 않는다. 다른 필수 관문은 유지한다.
- Issue 브랜치의 검사와 main pre-push, Issue·장부·측정·ship 기록은 유지한다.
  main에는 Issue 장부가 없어 pre-push만으로 시험 잠금 검사를 대체할 수 없다.
- ship 자동화, 검사 관문 변경, 측정 생략은 이번에 하지 않는다.

## 대안과 다시 볼 조건

- 문서 확장자로 검토를 생략: 지침의 실행 영향을 놓치므로 기각한다.
- main pre-push만 검사: Issue 장부 검사를 놓치므로 기각한다.
- ship 전체를 한 명령으로 자동화: 부분 성공과 재시도 비용을 늘리므로 보류한다.
  지침 정리 후에도 같은 준비 실수나 비용이 반복되면 로컬 사전 점검·초안 생성부터 검토한다.

## 검증 한계

이번 결정은 절차의 모호함을 줄인다. 실제 시간·토큰 절감은 아직 측정하지 않았다.
동종 작업에서 리뷰어 실행, push, CI 대기, ship 재작업을 관찰해야 한다.
기존 `activeMinutes`는 유휴 대기를 제외하므로 CI 대기 절감의 직접 증거가 아니다.
