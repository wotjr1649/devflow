# Delegation

**Exit:** the coordinator recovers and adjudicates the worker's scope, evidence, lifecycle and partial effects. A result/exit notification alone cannot accept a task.

## Select and brief

Load one role/perspective and the actual host adapter. New tasks and independent reviews use fresh context where supported; disclose inherited-context limits without counting contaminated/self review as an independent gate. Supply relevant project instructions and exact requirements. Settings/restrictions follow the exposed host contract and existing grants; role names, prompts, worktrees and successful launches do not prove isolation.

A brief contains:

- Role/perspective, one task/attempt, scope/criterion revision, repository/workspace and actual input head.
- Goal, files/interfaces/input fixtures, acceptance checks and constraints; relevant delivery scope/base.
- Allowed edits/commands/byproducts and excluded effects. Workers do not write Issue/ledger, push, integrate, expand scope or spawn descendants without a separately authorized assignment.
- Prior failed attempts/cause, remaining budget, decisions and dependencies; no expected verdict or unrelated history.
- Result contract: lifecycle separate from role verdict, exact subject/scope, edits/findings, real commands/exits, private evidence pointers, limits and next decision.

Supply operative role instructions once, inline or through a trusted readable artifact. Missing launch tools permit a complete brief, never a fabricated worker result. Required independent gates need actual eligible workers.

## Read/execute tripwire

Around every explorer/reviewer run the trusted helper's `delegation-check before`, retain its token, then `delegation-check after <token>` after exit. Unknown required coverage or unexplained changes keep delegated verification/review open. Retry after with the same token, never a new baseline absorbing worker effects.

The helper checks its recorded surfaces; after avoids Git against potentially changed code/configuration. It is a tripwire, not tool/network isolation or rollback. Exclude only named, authorized check byproducts—not broad ignored/untracked classes or unauthorized-change evidence. Native restrictions apply only when actually available.

Unexpected effects stop dependent acceptance/launches. Preserve receipts and inspect affected paths/processes/config before executing potentially changed code or Git; do not undo another actor's changes automatically. Static reviewers receive safe packages; verifiers execute only named checks with controlled byproducts. Missing guarantees hold only work requiring them.

## Lifecycle and acceptance

Record background work before launch with task/attempt/base/scope identity. Recover output before marking done. On timeout/interruption establish worker/descendant exit and partial effects; otherwise retain unknown activity, avoid conflicting relaunch and continue independent work. Exit confirmation grants no termination authority.

Completed FAILURES/FINDINGS reports are valid reporting. Compare with current head/criteria/inputs, inspect substantive evidence, adjudicate findings and explicitly accept/reject. Late/mismatched reports remain history unless revalidated; workers cannot overwrite phase/attempt or reset budgets.

M2 completes verify/review/acceptance before the next task. M3 normally launches two or three ready independent tasks together in verified-base worktrees, reviews each result and integrates serially. After each integration inspect overlap/dependencies and revalidate remaining patches/proof against the advancing head. Worktrees do not isolate shared Git config, ledger, remotes or services. Keep changed worktrees for cleanup's separate gate.

## Decisions and retries

NEEDS_DECISION pauses the affected edit; silence/notification is no answer. The coordinator resolves in-grant choices or asks the user, then resumes that task. A different task gets fresh context.

Inspect failure evidence before repair. Two unsuccessful repairs allow one recorded promotion/escalation; further failure needs an approach change, coordinator takeover within scope or a blocker. Three equivalent failures at a goal trigger approach review. Persist task attempts and explicit total budgets across sessions/phases/replacements; renaming the same goal cannot reset them. Hook continuation and host turn caps are separate. Promotion never expands authority.
