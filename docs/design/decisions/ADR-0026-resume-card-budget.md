# ADR-0026: 재개 카드는 실제 조립 출력으로 예산을 지키고, 넘치면 Tool 없는 고정 오류로 끝난다

상태: 채택 (#73, 2026-10-23 사용자 결정).

## 맥락

재개 카드는 예산(`estTokens` 1,000 미만)을 넘으면 상태 블록을 꼬리부터 지웠다. 그래서 템플릿 뒤쪽의 다음 행동·막힘이
먼저 사라졌다. 이유 한 줄만 내는 경로에는 축소가 없었고, repo·branch·장부 값·체크포인트 값은 길이와 타입 검사 없이
출력됐다. 문자열로 바꿀 수 없는 장부 값에서는 카드가 예외를 던져, 이미 확인한 경고와 `Tool:` 줄까지 잃었다.
`Tool:` 줄은 스킬이 Issue를 읽고 쓰는 유일한 경로이므로 잃거나 잘못 지어내면 안 된다.

## 결정

- 연결·작성자·공개 필터·Issue 번호 판단은 원문으로 하고, 표시만 줄인다. 모든 경로에서 실제로 조립한 출력을 예산과
  대조한다. 고정 상수로 예산 준수를 증명했다고 보지 않는다.
- 다음 행동·막힘·경고·`Tool:` 줄을 보호하고 나머지부터 줄인다. 줄인 값은 미리보기이며 원문 복구 전에는 미확인이다.
- 정상 카드가 들어가지 않으면 정확한 `Tool:` 줄을 둔 최소 오류 카드, 그것도 들어가지 않으면 상태·`Tool:` 줄·라우팅이
  없는 고정 오류로 끝난다. 고정 오류에도 확보한 경고는 남긴다. 예외도 같은 순서로 처리한다.
- `Tool:` 줄이 없는 카드로는 Issue 읽기·쓰기와 라우팅을 하지 않으며, 경로를 저장소에서 찾지 않는다.

## 결과

- 긴 상태·경고·경로에서도 다음 행동·막힘과 복구 수단이 남고, 예외가 경고와 `Tool:` 줄을 지우지 않는다.
- 고정 오류가 나는 환경(`Tool:` 줄만으로 예산 대부분을 쓰는 설치 경로)에서는 카드에 의존한 진행이 멈춘다. 오류에서
  더 느슨한 상태로 진행하는 대신 멈추는 쪽을 택한 대가다.
- 잘못된 장부 mode나 링크된 Issue 폴더에서 Issue 쓰기가 바로 게시되는 동작은 바뀌지 않는다. 카드는 그 사실을 보일
  뿐이며, 쓰기 정책은 별도 범위다.

## 검토한 대안

- 예산을 넘은 카드를 그대로 출력: 예산 계약이 깨지고 compact 뒤 재주입량이 커진다.
- `Tool:` 경로를 줄이거나 추정: 잘못된 실행 경로를 만들 수 있다.
- `Tool:` 길이에 고정 상한(예: 400)을 두기: 실제로 들어가는 출력도 거부한다.
