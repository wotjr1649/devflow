# Delivery

Done when the scoped effect is integrated and observed at its destination, or the exact unresolved effect and missing prerequisite are recorded. Confirm the current target and authority first.

## Readiness and publication

Readiness and review return evidence without writes. Check repository, revision, scope, approval, review and preserved behaviour against the exact candidate. Report check kind, environment, revision, result and source, including failed, unexecuted and unreadable checks. Keep private paths, prompts and logs local. Draft public effects if authority is missing.

Use conditional execution or provider protection for concurrent writes. Refresh the target before each effect and read it back after. Record partial effects. Retry only when proven unapplied and ended or covered by verified idempotency. For deployment verify environment, artifact, health and rollback gates.

## Ship

For tracked delivery, follow the project's integration profile and use the trusted Tool on the Issue branch. Record planned operations in ledger notes during unattended mode and defer Issue publication, pushes and integration. For a full ship, check off only evidenced criteria and post the verified checkpoint, then take the appropriate path:

1. Under `pr-ci`, use successful CI whose workflow actually runs the declared verify on the exact head. Run verify locally if that result is unavailable and still wait for all required CI. Under `local-merge` and `push-on-request`, run the local verify. Reconcile changed and preserved behaviours and investigate failed required checks before rerunning at the current revision. Keep the Issue open for a partial ship, returning remaining work to build or plan.
2. Apply the project's trigger and behaviour evaluation policy for routing or guard changes. Record results and limits. Use paid runs only when authorized.
3. For a full `local-merge` or `push-on-request` write the done state, note remaining push and cleanup, and close before integration. For `pr-ci`, record ship and keep the Issue open pending confirmed merge. Reopen a premature closure and return to build for failed checks or ship for a rejected push.
4. Prepare the PR with scope, exclusions, criteria, verification, pending work, public summary, reviewed SHA and `Refs #<n>`. Omit auto-closing keywords from PR, commits and merge message. Use local draft if remote metadata is unavailable. A required independent review covers M0. Author self-review or an unexecuted draft does not supply it.
5. Bind required proof to trusted workflow, repository, run/attempt, event and exact checkout for head, merge tree or integrated revision. Confirm execution and preserved coverage against approved assertions. Missing, skipped, cancelled, stale, foreign or weakened proof is NOT_VERIFIED. An exit code or local substitute cannot satisfy hosted checks. Report the missing condition and hold integration.
6. Refresh base, head, rules, CI, approvals and threads. Integrate by the project's approved method without bypass and use an expected-head guard, e.g. `gh pr merge <n> --merge --match-head-commit <sha>`. Recheck the destination's result and post-merge gates. Under `pr-ci`, mark the Issue done and close from its branch only once the merged result and all criteria are verified.
7. Report verified closed, open and unknown trackers. Evaluate each tracker against its own scope, dependencies, evidence and authority. Keep partial work open. Reuse existing follow-ups before creating an authorized successor; carry evidence, links, prerequisites and next action. Verify reciprocal links before closing a transfer. Use agreed evidence for local-only delivery.

In the report, check off only observed exits of this sequence, including optional eval status, verified destination and any successor or closure conditions.

## Cleanup

Inventory and prove each target independently. Confirm scope, intended base, verified integration, tip, owner, active use, occupancy, locks, submodules, post-merge or detached changes, and staged, unstaged, untracked and ignored state. Squash or rebase needs change-equivalence evidence and preservation of unique history. Keep protected or default branches, the main worktree, active or unrelated work, and uncertain targets. A readiness request inventories and reports without deleting. Tracking readiness uses the separate completion gate.

Before removal settle uncommitted files and preserve authorized nonreproducible material in a verified, Git-ignored path outside the target. Refuse redirects, secrets, insufficient space, and unverified copy or restore; record hashes and Git state. Keep unintegrated or active work. Avoid force, reset, clean and pruning as substitutes.

Recheck current source, scope, tips and active use right before mutation. Remove the worktree with `git worktree remove <path>` and the local branch with `git branch -d <branch>` before the remote branch. Read a remote tip with `git ls-remote <remote> <full-ref>`; remove with `git push <remote> --delete <branch>` only while its nonempty SHA matches the reviewed target without a protection bypass, lease, force or ref overwrite. A moved tip, refusal or unavailable operation holds the target. Read back and report removed and held targets, preservation, evidence, revisit date and remaining prerequisites. Use `note` with the original Issue number while its ledger exists.

Report a checklist per target for identity, integration, preservation, latest tip and use checks, authorized removal and readback.
