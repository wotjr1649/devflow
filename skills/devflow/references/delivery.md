# Delivery

Done when the scoped effect is integrated and observed at its destination, or the exact unresolved effect and missing prerequisite are recorded. Confirm the current target and authority first.

## Readiness and publication

Review-only and readiness requests return findings or observed readiness without edits or external effects. Scope each prerequisite to the action it gates. Verify repository, root, base/head, review evidence, request scope, criteria and project policy. Check acceptance and preservation against the current revision, checked-out merge result or exact non-Git artifact. Report every check's kind, method, environment, revision, result and source. Distinguish observed, supplied and unknown facts, and keep failures and unreadable evidence visible. Report unexecuted actions and why. Publish reviewed summaries through authorized channels, keeping secrets, private paths, prompts and raw logs in authorized local locations. Draft an externally visible action when authority is missing.

Use conditional execution or provider protection for concurrent mutations. Refresh state immediately before each effect and read it back after. Record partial success. Retry only after verifying that the same request is unapplied and ended or that verified idempotency covers the uncertain outcome. Never use uncertainty to infer absence. Reconcile a PR or deployment by its live repository, environment and artifact, including project health and rollback gates.

## Ship

For tracked delivery, follow the project's integration profile and use the trusted Tool on the Issue branch. Record planned operations in ledger notes during unattended mode and defer Issue publication, pushes and integration. For a full ship, check off only evidenced criteria and post the verified checkpoint, then take the appropriate path:

1. Under `pr-ci`, use successful CI whose workflow actually runs the declared verify on the exact head. Run verify locally if that result is unavailable and still wait for all required CI. Under `local-merge` and `push-on-request`, run the local verify. Reconcile changed and preserved behaviours and investigate failed required checks before rerunning at the current revision. Keep the Issue open for a partial ship, returning remaining work to build or plan.
2. Assess trigger evals for a change to skill selection or trigger fixtures and behaviour evals when routing or guardrails change. The optional trigger eval runs in the authenticated user's terminal. With prior paid-run authority, repeat affected behaviour cases three times and use fresh-context review of tool traces and answers. Record what ran, results and limits. Apply any explicitly agreed criterion without inventing a gate.
3. For a full `local-merge` or `push-on-request` write the done state, note remaining push and cleanup, and close before integration. For `pr-ci`, record ship and keep the Issue open pending confirmed merge. Reopen a premature closure and return to build for failed checks or ship for a rejected push.
4. Prepare the PR with scope, exclusions, criteria, verification, pending work, public summary, reviewed SHA and `Refs #<n>`. Omit auto-closing keywords from PR, commits and merge message. Use local draft if remote metadata is unavailable. A required independent review covers M0. Author self-review or an unexecuted draft does not supply it.
5. Bind each required check to its trusted workflow, repository, run, attempt, event, base, head and checkout. Head checks require current HEAD; PR checks require the current base/head merge tree; post-merge checks require the integrated revision. A skipped, missing, cancelled, stale, wrong-source or weakened check is NOT_VERIFIED. Confirm effective coverage and execution of required assertions against the approved check definitions, including preserved behaviour. An unrelated same-name result, shell exit alone or a local substitute cannot satisfy a hosted gate. Zero checks leaves readiness unverified unless the project's authorized local gate and PR evidence apply. Report the exact missing or failed condition. Do not merge, call it ready, or offer to accept a required check gap.
6. Refresh base, head, rules, CI, approvals and threads. Integrate by the project's approved method without bypass and use an expected-head guard, e.g. `gh pr merge <n> --merge --match-head-commit <sha>`. Recheck the destination's result and post-merge gates. Under `pr-ci`, mark the Issue done and close from its branch only once the merged result and all criteria are verified.
7. Report verified closed, open and unknown trackers. For linked Issues or milestones, check each one's own scope, criteria, dependencies, post-merge or release gate, completeness of inventory and authorization. Keep partial Issues open. Search existing work before creating an authorized follow-up for a user-decided deferral or reproduced defect. Propose other remnants together. Give each successor scoped evidence and criteria, links, dependencies and next action, and read back authorized reciprocal links before closing a transfer. Completion and deletion each require their own authority. Local-only delivery uses its agreed artifact or install evidence.

In the report, check off only observed exits of this sequence, including optional eval status, verified destination and any successor or closure conditions.

## Cleanup

Inventory and prove each target independently. Confirm scope, intended base, verified integration, tip, owner, active use, occupancy, locks, submodules, post-merge or detached changes, and staged, unstaged, untracked and ignored state. Squash or rebase needs change-equivalence evidence and preservation of unique history. Keep protected or default branches, the main worktree, active or unrelated work, and uncertain targets. A readiness request inventories and reports without deleting. Tracking readiness uses the separate completion gate.

Before removing a worktree, settle its uncommitted files and preserve nonreproducible material the user authorized. Put archives in an unoccupied, authorized, Git-ignored real path outside the target, normally `artifacts/worktree-archive/` under the primary checkout. Reject symlink or reparse redirects. Inventory size, hashes, metadata, root, revision, refs, commits and worktree/index restoration. Check space and verify copy and restore. A partial or stale archive blocks deletion. Avoid copying secrets and whole reproducible checkouts. Do not delete unintegrated or active work or offer or run forced removal, reset, clean, or pruning as a substitute.

Recheck current source, scope, tips and active use right before mutation. Remove the worktree with `git worktree remove <path>` and the local branch with `git branch -d <branch>` before the remote branch. Read a remote tip with `git ls-remote <remote> <full-ref>`; remove with `git push <remote> --delete <branch>` only while its nonempty SHA matches the reviewed target without a protection bypass, lease, force or ref overwrite. A moved tip, refusal or unavailable operation holds the target. Read back and report removed and held targets, preservation, evidence, revisit date and remaining prerequisites. Use `note` with the original Issue number while its ledger exists.

Report a checklist per target for identity, integration, preservation, latest tip and use checks, authorized removal and readback.
