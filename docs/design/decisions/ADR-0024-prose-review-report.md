# ADR-0024: 리뷰 보고는 짧은 산문으로 하고 구조화 보고 CLI를 두지 않는다

상태: 채택 (#68).

## 맥락

#68의 행동 검증에서 Claude가 근거 없이 "독립 리뷰가 안 됐다"고 단정하는 실패가 반복됐다. 이를 막으려고 별도 가지에서
리뷰 상태를 JSON으로 받아 검증·렌더링하는 `devflow-review-report` CLI와 그 계약 spec, 8개 섹션 보고를 만들었다.

측정 결과 그 경로는 리뷰 1회 읽기를 622토큰에서 8,296토큰으로, 보고서 중앙값을 약 2.6KB에서 약 72KB로 늘렸다.
Claude의 통과율은 나아지지 않았고(도입 전 5/1, 도입 후 최고 5/0/1·5/1), 같은 상태 단정도 검증된 보고서 안에서 다시
나왔다. 개수·읽기 권한·인용부호 오기, JSON 거부처럼 보고 표면이 넓어진 데서 오는 실패도 생겼다.

## 결정

- 리뷰 보고는 SKILL.md와 phase review의 산문 규칙으로 한다. 구조화 보고 CLI·spec·8개 섹션 의무는 두지 않는다.
- 규칙은 요구사항이나 여러 번 재현된 실패가 있을 때만 더한다. 한 번 나온 실패에 맞춘 문장은 더하지 않는다.
- 리뷰 상태 근거와 readiness 연결 규칙은 `.devflow.json`이 없어도 읽히는 phase review에 둔다.

## 대안과 다시 볼 조건

- CLI 유지: 구조화 입력의 상태 충돌·근거 없는 상태 거부는 실제로 동작했지만, 분량 대비 Claude 오류 감소가
  확인되지 않아 기각했다.
- 상태 전용 CLI만 유지: 일반 리뷰에서 호출할 계기가 없어 쓰이지 않는 코드가 되어 기각했다.
- 산문 규칙으로 같은 상태 단정이 반복 재현되고 그 원인이 문안이 아니라 표현 형식으로 확인되면, 작은 구조화
  상태 검증을 다시 검토한다.
